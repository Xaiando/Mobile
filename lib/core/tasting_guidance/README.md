# Guided observation and original calibration API

Root appends three original grids `tg_guided_wine_l1_v1`, `tg_guided_wine_l2_v1`, `tg_guided_wine_l3_v1` to the authored curriculum without changing existing grids/keys. Root includes and authors `assets/study/guided_tasting.json`:

```json
{"schemaVersion":1,"version":"1.0.0","levels":[{"level":1,"gridId":"tg_guided_wine_l1_v1","evidencePrompts":[{"id":"description","prompt":"Explain the observations supporting your description."}]},{"level":2,"gridId":"tg_guided_wine_l2_v1","evidencePrompts":[{"id":"description","prompt":"Explain your description using observed structure and flavours."}]},{"level":3,"gridId":"tg_guided_wine_l3_v1","evidencePrompts":[{"id":"quality","prompt":"Explain quality using observed balance, length, intensity and complexity."},{"id":"ageing","prompt":"Explain whether the wine should develop, using its structure and flavour development."}]}],"cases":[{"id":"original_l1_case","level":1,"title":"Original training case","description":"A fictional or described wine scenario.","itemIds":["ki_example"],"referenceObservations":[{"attributeKey":"sweetness","valueKeys":["dry"],"explanation":"Reasonable description in the stated scenario."}],"criteria":[{"id":"evidence","text":"Support the description with scenario evidence."}],"feedback":"Original transparent training explanation, not marks for a physical unknown wine."}]}
```

Cases require current effectively mapped canonical fact links at their level and valid grid reference values. Reference values may describe a reasonable range/list and do not receive automatic binary marks. Physical-wine mode uses the same grids, optional journal link, observation choices and saved evidence, with no objective score. Case prompts, reference observations, criteria, feedback and level evidence prompts are snapshotted per session; feedback appears after completion. Written criteria are learner self-assessment only. No FSRS or official pass side effects.

Observations use existing `TastingPractice`/tasting session and descriptor tables. Evidence metadata uses backed-up settings keys `guided_tasting_record_v1_<session UUID with hyphens replaced by underscores>` plus current pointer `guided_tasting_current_v1`. UUID values retain their original spelling; only setting names are sanitized for the existing schema. Completion requires required grid observations and nonblank evidence for each prompt. Repeated finish is transactional and idempotent. Changes made to the session through the legacy recorder reopen the guidance metadata, clearing the old completion/self-check; old grid definitions are untouched. New bank versions never replace an existing session's prompt/feedback snapshot.

Root wires route/navigation to `GuidedTastingScreen`, includes the JSON asset, and owns separate progress/outcome/remediation activity. `history()` exposes records and their completion/evidence; session timestamps come from existing tasting sessions. The Level 3 paired two-wine/30-minute tasting rehearsal is not implemented in this batch. Guided descriptive and evidence practice is untimed; do not label it that official examination format.
