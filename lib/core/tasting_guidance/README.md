# Guided observation and original calibration API

The curriculum includes three original grids: `tg_guided_wine_l1_v1`, `tg_guided_wine_l2_v1` and `tg_guided_wine_l3_v1`. They preserve existing grid IDs and saved observation vocabulary. The authored bank is `assets/study/guided_tasting.json`, currently version `1.1.0` with schema version `1`.

| Study level | Written evidence in new sessions |
|---|---|
| Level 1 | Description |
| Level 2 | Description and a tentative quality conclusion supported by observations |
| Level 3 | Description, quality and possible development |

The Level 2 quality conclusion uses an original written prompt rather than adding an observation choice or reproducing the proprietary SAT. Its 17 observation attributes remain unchanged. The prompt asks the learner to weigh strengths and limitations, explain the relationship between flavour and structure, and separate quality evidence from personal liking. This supports the quality-conclusion topic in the [current public Level 2 tasting reference](https://www.wsetglobal.com/media/19131/wset_l2wines_sat_en_aug2026_issue21.pdf); it is not an official tasting grade.

There are three fictional calibration cases at each level. A case has an ID, level, title, description, current mapped `itemIds`, `referenceObservations`, self-assessment `criteria` and delayed `feedback`. The three Level 2 cases include a `quality` criterion and discuss the available evidence and its limits. Cases require current effectively mapped canonical fact links and valid grid reference values before starting. Reference values may describe a reasonable range or list and receive no automatic binary marks. Physical-wine mode uses the same grids, optional journal links, observation choices and saved evidence, with no objective score. Written criteria are learner self-assessment only; no review-state, FSRS or examination-pass side effects occur.

Observations use the existing `TastingPractice` session and descriptor tables. Evidence metadata uses backed-up settings keys `guided_tasting_record_v1_<session UUID with hyphens replaced by underscores>` plus the selection pointer `guided_tasting_current_v1`. UUID values retain their original spelling; only setting names are sanitized. Completion requires every required grid observation and nonblank evidence for every prompt in the saved session contract. Repeated finish is transactional and idempotent. Changes made through the legacy recorder reopen stale guidance completion, clearing the old completion and self-assessment while retaining written evidence.

Case references, criteria, feedback, bank version and level evidence prompts are snapshotted per session. A new bank never overwrites an existing session's prompt or feedback contract. Earlier Level 2 drafts can finish with their saved description-only contract, and earlier completions remain readable. Backup and restore preserve both older records and newer quality evidence. The bank change requires no database schema migration.

Current practice requirements are separate from historical record validity. The shared WSET scope can declare `guidedEvidenceIds`. Its Level 2 requirement is `["description", "quality"]`, so only completed calibration snapshots whose saved contract contains both prompts and nonblank evidence can count toward the current Level 2 practice milestone. A valid older completion lacking quality stays in history and is not reported as corruption. This measures recorded participation, not whether the written quality conclusion is correct. Missing or malformed practice remains distinguishable from valid history that does not satisfy current requirements.

`GuidedTastingScreen` provides untimed single-wine guidance, original calibration feedback and saved-session history. `history()` exposes saved evidence and completion; timestamps come from the existing tasting sessions. Level 3 also has a separate [paired tasting practice](../tasting_pair/README.md): two physical wines share a persisted 30-minute deadline, and each wine keeps its own observation and evidence snapshot. Its recorded white-and-red pair can support the configured app participation milestone. The app cannot authenticate either wine's identity, colour or still-wine status, and neither guided nor paired practice awards an official qualification.
