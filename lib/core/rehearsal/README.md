# Original WSET practice bank API

Bank asset: `assets/study/wset_rehearsal.json`. `RehearsalBank.fromJson` expects:

```json
{"schemaVersion":1,"version":"1.0.0","levels":[{"level":1,"mcqCount":30,"writtenCount":0,"durationSeconds":2700},{"level":2,"mcqCount":50,"writtenCount":0,"durationSeconds":3600},{"level":3,"mcqCount":50,"writtenCount":4,"durationSeconds":7200}],"mcqs":[{"id":"l1_styles_01","prompt":"Original question","levels":[1,2,3],"itemIds":["ki_example"],"options":[{"id":"a","text":"One answer"},{"id":"b","text":"Another answer"}],"correctOptionId":"a","explanation":"Original explanation supported by linked facts."}],"written":[{"id":"l3_explain_01","prompt":"Original written question","levels":[3],"criteria":[{"id":"cause","text":"Original self-assessment criterion","itemIds":["ki_example"]}]}]}
```

IDs must be unique. Every linked fact must be current and effectively mapped to the selected active WSET level to enter sampling. The full preset requires enough unique eligible questions; it never silently shortens. Written prompts are Level 3 only. Original educational scoring uses one point per correct MCQ; written criteria are learner self-assessment after finishing. These scores are not official marks or qualification results.

Optional blueprint support: a level row may include `"blueprint":{"process":6,"styles":18,"service":6}`; each MCQ may include `"blueprintByLevel":{"1":"styles","2":"principal","3":"still"}`. Bucket names are editorial IDs. Counts must be positive and sum to that preset's MCQ count. Sampling takes unique eligible questions from each bucket and shuffles the combined set; a short bucket fails clearly. Confirmed proportions: L1 process 6/styles 18/service 6; L2 vine 5/winery 4/principal 19/regional 12/sparkfort 6/service 4; L3 factors 8/still 28/sparkling 5/fortified 5/service 4. The root-authored bank owns exact bucket naming, original questions and canonical fact links.

Attempts store an immutable prompt/options/explanation/rubric snapshot and answers in `user_settings` under `wset_rehearsal_attempt_v1_<uuid_with_underscores>`. `wset_rehearsal_current_v1` selects the latest attempt with its real UUID. Existing backup exports these keys. Finishing/expiry freezes answers; repeated or concurrent finish calls read the same persisted completion. A rejected late answer commits expiry before throwing its error. New attempts keep previous snapshots. Abandoning retains the draft as an abandoned history entry.

The absolute UTC deadline continues while the app is closed. There is no timer-reset pause. Current read, answer writes and finalization enforce the deadline. Saved snapshots require canonical UTC timestamps, exact preset duration, matching UUID/settings identity and completion within the saved interval; expiry completes at its deadline. A clock rewind never displays more than the preset duration. Blank written answers cannot claim self-assessed criteria. Wall-clock tampering is not prevented by an offline app. No automatic FSRS updates occur: multi-fact questions and self-assessed prose do not establish card-level mastery, and historical/current bank changes must not relabel shared memory blindly. Root owns progress/outcome integration.

Wiring: include the bank asset in pubspec and route/navigation to `RehearsalScreen` from `lib/features/rehearsal/rehearsal_screen.dart`. The module's providers wait for existing app startup. Screen start explicitly selects the chosen WSET track through LearnerProfiles, then the repository verifies that track before sampling. Historical activity is available through `RehearsalRepository.history()`; every attempt exposes level, times, finishReason, original MCQ score, prose and criterion self-assessment. Root owns separate progress activity and remediation links.
