# Audio notes and review exports (0.4.4+22)

Tasting → Notes and wine, completed tastings, and Guided tasting have an Audio notes panel. Enter a title, record, pause/resume, and Stop and save. Saved recordings can be played, stopped, downloaded or deleted. Permission is requested only when recording starts. Recording pauses when the app becomes inactive; this is foreground recording, not a background recorder. Finish/delete/leave/import/erase controls protect unsaved captures. A failed database save retains a bounded capture for Retry saving or Download unsaved audio. Download alone does not discard the unsaved copy.

Recordings live locally as versioned metadata and base64 data pairs in the existing backed-up `user_settings` table. No schema migration, curriculum alteration or device-specific paths. Bytes and SHA-256 are checked on read and backup import. Deleting a tasting deletes both attachment rows in the same transaction. Reset progress preserves recordings; Erase All removes them. The regular JSON backup carries audio across supported app platforms. Older app versions do not display this new attachment type; use 0.4.4+22 or later when restoring audio.

Native recording prefers mono AAC/M4A at 32 kbps and 16 kHz. Browsers use AAC if supported, otherwise Opus in the actual browser container (WebM/Ogg), then WAV. Maximum recording time is two hours, per-recording storage 32 MiB, total stored audio 48 MiB. WAV fallback stops after 15 minutes. Device encoders can change bitrates. A recording up to 64 MiB can be retained temporarily for download when too large to store. Files retain their actual MIME/container and extension. Cross-platform playback depends on receiving codecs; an exported WebM/Ogg can be opened in a compatible browser/player if native playback fails. Browser recording needs localhost or HTTPS and microphone access. No cloud transcription or upload.

Settings → Your data → Download test results for review saves a ZIP with readable `report.html` (browser Print → PDF), structured `report.json`, and CSV review/tasting tables. Extract the ZIP before opening the HTML. Audio is unchecked by default. A tasting's download action exports just that tasting and its guided evidence, if present. Global exports include saved WSET/CMS rehearsals, Diploma written and tasting records (including D3 timed papers), paired/guided tastings and the D6 draft. Full private backups remain a separate restore feature.

Review reports omit journal photos, onboarding/account settings and FSRS scheduling internals. They contain personal answers and notes and are unencrypted. Ask permission before recording people and choose who receives an export. The app does not submit it to a reviewer.

Practice MCQ scores are reported only where the stored original attempt supports grading. FSRS ratings remain memory ratings; written/tasting rubrics remain self-reviews. Current curriculum question/assertion context is labelled as current, not an exact historical reconstruction. Unavailable context stays null. Editable reports and hash manifests are not authenticated exam certificates. Original saved attempt snapshots include their prompts, criteria, answers, dates and abandonment/in-progress state. Corrupt saved attempts are explicitly included with warnings rather than falsely graded or silently removed. An export above 64 MiB or 50,000 rows per section fails without silently dropping records. Use individual tasting reports or omit audio for large exports. The existing private backup also has a 64 MiB ceiling; export recordings separately if the combined backup exceeds it.

Android RECORD_AUDIO and iOS NSMicrophoneUsageDescription declarations are included in this isolated feature source. Android integration belongs to the Android branch owner; permission denial, interruption, speaker/Bluetooth playback and backup transfer need physical device validation. No macOS runner exists in this project; adding one requires audio-input entitlement and microphone usage description. Windows microphone privacy settings can prevent recording.

Implementation references: [record documentation](https://pub.dev/packages/record), [audioplayers documentation](https://pub.dev/packages/audioplayers). New packages are pinned by pubspec.lock. Plugins use their native/browser engines; no audio is uploaded.
